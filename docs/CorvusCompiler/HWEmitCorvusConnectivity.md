# HWEmitCorvusConnectivity Pass

## TODO

- 这个 Pass 插入在 corvus-compiler 的 hw::createHWPartitionModules 之后

- 这个 Pass 输出一个 JSON 文件，描述 Corvus Compiler 产生各个模块之间的连接关系
  - 输出文件的路径由 --hw-emit-corvus-connectivity-json=<path> 参数指定
  - 该参数默认为空字符串，则跳过这个 pass，不写文件

- 为了阐述这个Pass的功能，需要对模块类型分类进行定义
  - 顶层模块：类型为 public 的 hw.module
  - 分区模块：具有 __corvus_partition 属性的 hw.module
  - 普通模块：其他 hw.module

- 输入设计中的模块满足以下性质，如果实际运行时不符合以下性质则报错
  - 顶层模块有且仅有一个
  - 每个分区模块至多有一个 instance，因此通过 hw.module 的 moduleName 可以唯一区分
  - 分区模块的输入端口和顶层模块的输出端口满足以下性质
    - 必须由 顶层模块的输入端口 或 分区模块的输出端口 “最终驱动”
    - “最终驱动” 的定义：如果一个端口 A 直接连接到端口 B，则 A 驱动 B；如果 A 驱动 C，且 C 驱动 B，则 A 最终驱动 B
    - 驱动路线上仅允许穿过 blockArgument、hw.instance、hw.output 的组合，不允许有其他 Op

- 输出 JSON 文件的内容符合以下格式
```
{
  "top":{
    "moduleName": "<顶层模块名称>",
    "inputs": {
      "端口0名称": {
        "W": <位宽（整数）>
      },
      "端口1名称": {
        "W": <位宽（整数）>
      },
      <...其他输入端口...>
    },
    "outputs": {
      "端口0名称": {
        "W": <位宽（整数）>,
        "M": "<最终驱动该端口的模块名称>", 
        "P": "<最终驱动该端口的模块的端口名称>"
      },
      "端口1名称": {
        "W": <位宽（整数）>,
        "M": "<最终驱动该端口的模块名称>", 
        "P": "<最终驱动该端口的模块的端口名称>"
      },
      <...其他输出端口...>
    }
  },
  "partitions": {
    "分区模块0名称": {
      "inputs": {
        "端口0名称": {
          "W": <位宽（整数）>,
          "M": "<最终驱动该端口的模块名称>", 
          "P": "<最终驱动该端口的模块的端口名称>"
        },
        "端口1名称": {
          "W": <位宽（整数）>,
          "M": "<最终驱动该端口的模块名称>", 
          "P": "<最终驱动该端口的模块的端口名称>"
        },
        <...其他输入端口...>
      },
      "outputs": {
        "端口0名称": {
          "W": <位宽（整数）>
        },
        "端口1名称": {
          "W": <位宽（整数）>
        },
        <...其他输出端口...>
      }
    }
    <...其他分区模块...>
  }
}
```

- 输出 JSON 应该满足的性质
  - 顶层模块的 inputs 和 outputs 须列出所有的顶层端口
  - 存在实例的分区模块都必须在 partitions 中有对应项
  - partitions 中列出的分区模块的 inputs 和 outputs 须列出所有的端口
  - 每个端口的 W 必须正确反映该端口的位宽
  - M 字段为被实例化的模块名称而不是实例名
  - 顶层模块的 outputs 的 M 和 P 必须正确反映最终驱动该端口的模块和端口
    - 如果 M 为顶层模块的输入端口，则 M 为顶层模块的 moduleName，P 为该输入端口名称
  - 每个分区模块的 inputs 的 M 和 P 必须正确反映最终驱动该端口的模块和端口
  - 顶层模块的 inputs 的 M 和 P 不需要填写
  - 每个分区模块的 outputs 的 M 和 P 不需要填写

- 你可以使用 LLVM 提供的 JSON 库来生成 JSON 文件

- 建议的流程
  - 遍历所有 hw.module，找到顶层模块和所有分区模块
  - 对于每个分区模块，遍历其输入端口，找到最终驱动该端口的模块和端口，记录在一个映射中
  - 对于顶层模块，遍历其输出端口，找到最终驱动该端口的模块和端口，记录在一个映射中
  - 构造 JSON 对象，填入顶层模块的信息和所有分区模块的信息
  - 将 JSON 对象写入文件

- 出现失败时，尽可能提供详尽的报错信息，例如：
  - 顶层模块不唯一
  - 分区模块实例化多次
  - 驱动路径中出现不允许的 Op
  - 找不到最终驱动的模块或端口
